# CueFlow Timeline（秒级演示脚本调度）

一个**独立实现、免费、完全离线**的 Obsidian 桌面插件，交互设计参考 dotpm 的甘特图思想，但针对发布会演示、无人机多设备协作演示和舞台 Run of Show 重新设计。

> **版本 0.9.0**：完整 JSON / Markdown 项目导入导出，包含 AI 优化目标、约束与完整数据；AI 返回的文件或粘贴内容可预览后保存为新项目。保留框选、多动作整体调整与关键星标。

[下载 v0.9.0 安装包](dist/cueflow-plugin-v0.9.0.zip) · [验收摘要](docs/VALIDATION.md) · [MIT 许可证](LICENSE)

![CueFlow 多选动作与关键星标](docs/images/timeline.png)

## 主要功能

| 功能 | 说明 |
|---|---|
| 秒级时间轴 | 从 `T+00:00` 开始，可采用 `1/5/10/30/60 秒`吸附，精确到秒 |
| 高精度拖拽 | 拖动移动时间与泳道，边缘拉伸调整时长；接近其他动作起止点时显示虚线对齐提醒 |
| 框选与批量调整 | 空白拖框多选；整体移动时间与泳道，选框两端等比例调整时间跨度 |
| 关键动作星标 | 单独或批量添加/取消星标，在详情、项目保存与导出中保留 |
| 多角色/设备 | 新建泳道时填写名称并选择分组，可修改名称、颜色、组内排序或调整归属 |
| 自定义分组 | 支持导播组、飞手组、无人机组等任意分组；可改名、排序、折叠/展开；删除分组保留泳道和动作 |
| 时间轴缩放 | 显示设置、加减按钮或 Ctrl+滚轮缩放；适应窗口查看完整排程；逐秒拖拽建议 600–900 px/分 |
| 人员/设备紧凑显示 | 标准泳道 74、紧凑泳道 40；在显示设置或工具栏切换，偏好自动保存 |
| 四节点连线 | 拖动左右节点建立前后依赖，上下节点建立关联/目标；循环依赖会被阻止 |
| 连线标注 | 默认无文字，双击连线添加、修改或清空标注；不改变排程 |
| 自动顺延 | 前置任务延期、后置任务发生冲突时，自动把后置任务推后；可关闭 |
| 可调列宽 | 拖动左栏标题右边界，160–600 像素；实时对齐并保存，支持键盘和双击恢复默认 |
| 任务配置 | 名称、泳道、相对开始时间、持续时间、状态、备注、多项前置任务 |
| 里程碑 | 设定持续时间为 `00:00`，呈现菱形标记 |
| 并行冲突 | 同一泳道时间重叠时，任务显示红色虚线边框（只提示，不阻止） |
| 排练时钟 | ▶ 排练 / 暂停 / 归零，红线跟随相对时间，当前任务高亮 |
| 离线存储 | 每个项目保存在 Vault 中的一个 `.md` 文件内，`cueflow` JSON 代码块可直接编辑 |
| 导出 | 导出 CSV 排程表与独立 SVG 矢量甘特图，适合 PPT |
| 撤销/重做 | 当前视图中最多保留 60 次快照，关闭后不保留历史 |

## 最简单安装方式（Windows）

1. 退出 Obsidian（或安装后重新加载 Obsidian）。
2. 解压 `cueflow-plugin-v0.9.0.zip`。
3. 把解压出来的文件夹 `cueflow-timeline` 复制到你的 Vault 插件目录，例如：

   ```text
   D:\\你的Obsidian知识库\\.obsidian\\plugins\\cueflow-timeline\\
       ├─ main.js
       ├─ manifest.json
       └─ styles.css
   ```

   注意：不要多嵌套一层 `cueflow-timeline/cueflow-timeline/`。

4. 重启 Obsidian → 设置 → 第三方插件 → 启用 `CueFlow Timeline`（若提示受限模式，先允许第三方插件）。
5. 点击左侧日历时钟图标，或 `Ctrl + P` 搜索 `打开演示脚本时间轴`。
6. 首次开启会在 Vault 的 `CueFlow/` 文件夹中自动生成一个「无人机空地协同演示（示例）」项目。

插件无需 npm、无需联网、无需 TaskNotes / dotpm / Gantt Calendar，**不要**把源码 ZIP 放到插件目录代替安装 ZIP。

## 设置总时长

点击工具栏「总时长」，或进入「显示设置 → 时间轴总时长」。可直接输入 `30:15`（30 分 15 秒）或 `01:30:00`（1 小时 30 分），也可用 `+1 / +5 / +10 分钟` 快捷增加。点击「保存总时长」后自动保存到项目，支持撤销/重做。

总时长精确到秒，支持 1 分钟至 24 小时。缩短时不能早于最后一个动作结束；后续动作超出原范围时自动延长并保存。总时长会同步用于时间轴、适应窗口、排练终点及 SVG 导出。

## 泳道拖拽

按住泳道左侧 `⠿` 手柄上下拖动，插入线标明松开后的位置。拖到其他分组的泳道可指定插入顺序；拖到分组标题会移入组末。支持空分组和折叠分组，移入后自动展开。按 Esc 可取消。

移动后人员/设备名称、动作时间与依赖关系保持，泳道归属和顺序自动保存，支持撤销/重做。标准、紧凑两种显示模式均可使用。

## 整组拖拽

按住分组左侧的 `⠿` 手柄上下移动。预览包含该组的全部可见泳道和动作，插入线标明整组落点。松开后，组内顺序、动作时间和依赖关系保持；支持空组、折叠组、Esc 取消、撤销/重做和保存重开。系统的「未分组」区域固定在末尾。

## 调整执行人员 / 设备列宽

按住「执行人员 / 设备」标题右侧的竖向分隔线，向左或向右拖动。列宽范围 160–600 像素；名称区域随之变宽，时间刻度、动作与依赖连线同步对齐，松开后保存偏好。按 Esc 取消本次调整；双击分隔线恢复 182 像素。分隔线获得焦点后，可用左右方向键调整，Shift 加快，Home/End 设为最小/最大值。也可在「显示设置」或插件设置内调整列宽。

## 编辑项目、泳道和动作

- 「项目设置」可同时修改项目名称和总时长，支持撤销/重做；名称保存在项目数据中，原 Markdown 文件名保持。
- 双击泳道名称，或「⋯ → 编辑名称 / 分组 / 颜色」，修改人员/设备名称、归属与颜色。
- 双击动作，直接在任务条上修改标题，Enter 或失焦保存，Esc 取消；支持中文输入。
- 右键动作选择「编辑详情」，或选中后点击底部「编辑详情」，可修改名称、执行人员/设备、开始时间、持续时间、状态、备注、前置动作与关联标注。
- 分组的「⋯ → 修改分组名称」编辑分组名称；显示设置可调整缩放、列宽及紧凑显示，插件设置还可调整保存目录、时间吸附和依赖顺延。

## 框选、多动作整体调整与关键标记

在泳道空白处按住鼠标拖出选框，框内接触到的动作会被选中；支持反向框选。按住 Ctrl（macOS 为 Command）点击动作可加选或取消该动作；Shift 点击或按住修饰键拖框可加选。Ctrl+A 选中所有可见动作。点击空白或按 Esc 取消选中。

- **整体移动**：框选后按住其中任一动作移动，所有选中动作同步改变时间；上下拖动可跨泳道整体移动，保留相对时间和泳道间距。
- **整体拉伸**：拖动整体选框左右两端的手柄，固定另一端，按比例调整选中动作的起点、时长及间隔；拖动所选动作的边缘也可以整体拉伸。最短非零时长为 1 秒，里程碑保持零时长。
- **撤销与取消**：一次整体操作对应一次撤销；Esc 或取消拖动还原预览。Delete 直接删除全部所选动作及相应连线引用，Ctrl+Z 可恢复。
- **依赖保持**：依赖与关联的连接对象不变；开启依赖顺延时，未选中的后续动作仍可能按规则推后。若依赖约束导致无法保持整体调整，会拒绝这次操作；可一并选中相关前置/中间动作，或关闭依赖顺延后调整。
- **关键动作**：选中后点击底部「☆ 标为关键动作」，或在右键菜单选择「标记为关键动作」，任务条显示金色星标；支持批量添加和取消。动作详情也有「关键动作」开关。星标不改变时长、状态或依赖，里程碑同样可标记。

关键标记随项目保存，CSV 含「关键动作」列，SVG 显示星标。折叠分组后不再保留其中隐藏动作的选择，避免误改看不到的动作。

## 显示设置和紧凑显示

点击时间轴顶部「显示设置」，使用滑块放大或缩小时间轴。点击「适应窗口」查看整场排程；在「人员 / 设备显示」中选择「紧凑显示」，同屏容纳更多泳道。工具栏也提供快捷紧凑按钮。Obsidian → 设置 → CueFlow Timeline 中可设置默认缩放、泳道显示、时间吸附和依赖顺延；这些显示参数会立即应用。

## 保存状态与冲突处理

右下角显示「待保存」或「已保存」。若磁盘写入失败或排程被其他视图/编辑器修改，显示「未保存」并提供「重试保存」「保存为副本」「重新读取」。冲突不会覆盖磁盘上的新排程。关闭含未保存冲突的视图时会尝试创建恢复副本；如果磁盘本身无法写入，会明确提示失败。

## 五分钟学会操作

### 1. 新项目和泳道

顶部 `+ 项目` 新建演示方案；`+ 分组` 创建导播组、飞手组、无人机组等自定义分组。点击分组名可折叠/展开，分组右侧 `⋯` 可改名、排序或删除分组；删除后泳道移至「未分组」，动作不删除。

点击 `+ 泳道`，直接填写名称、选择所属分组，再点击「创建泳道」；空名称不能保存，取消不创建。分组右侧的 `+` 会预选当前分组。双击泳道名或选择泳道 `⋯ → 编辑名称 / 分组 / 颜色`，可同时改名和调整归属。泳道上移/下移仅在所属组内进行。新建和编辑支持撤销/重做。

CSV 增加「分组」列；SVG 按分组显示所有泳道，包含当前折叠的分组。旧版预设泳道自动归入执行人员/设备，其他旧泳道放在「未分组」，可自行调整。

### 2. 新增一个动作

- 点击顶部 `+ 动作`，或泳道上的 `+`。
- **双击泳道空白处**，在该位置立即创建任务，并直接输入名称。默认持续 60 秒，接近 24 小时终点时自动缩短；可拖动两端调整时长。
- 名称按 Enter 或失焦保存；Esc 放弃本次名称修改并保留已创建的「新动作」。中文输入法确认时不会提前提交。
- 单击动作仅选中；移入或选中动作时四个节点亮起。点击空白或其他区域清除动作、连线选中并取消未完成的连线预览。单击或拖动泳道空白处不创建任务。
- 在弹窗填写任务名、执行人/设备、开始时间（例如 `03:12`）和持续时间（例如 `00:45`）。
- 双击已有任务条直接修改标题；右键菜单可打开详情。按住任务条拖动可移动时间和泳道，两侧拉伸可改时长；轻微抖动不改变任务。
- 选中任务后按 **Delete 直接删除，无确认弹窗**，相关前置引用一并清理；Ctrl+Z 可以恢复任务与依赖。输入框中的 Delete 只删除文字。右键和底部删除按钮保留确认。

### 3. 精确拖拽到 1 秒

1. 时间轴右上方的 **吸附** 下拉选择 `1秒`。
2. 点击右侧 `+` 放大时间轴至 `600 px/分` 或 `900 px/分`。每秒约 10–15 像素，可以较轻松地准确拖动。
3. 按住彩色任务条中央移动时间，拖动两端把手调整时长。
4. 垂直拖动任务条也可以改变任务所属泳道。
5. 按住 `Ctrl` 并滚动鼠标滚轮，可以快速缩放（或使用 `+ / −`）。

例如把 `T+03:12` 向右拖动 1 秒变成 `T+03:13`，不需要手工编辑日期。

### 4. 拖动连线与文字标注

鼠标移入或选中动作时，四个节点亮起，移开且未选中时隐藏。

- 从前置动作的右节点拖到后续动作的左节点，建立完成后开始的依赖。也可从后续动作左节点反向拖至前置动作右节点，依赖方向保持一致。依赖线为实线；开启「依赖顺延」后，后续动作会按需推后。
- 从上/下节点拖向其他动作的上/下节点，建立关联或目标箭头。关联线为虚线，只表示关系，不修改开始时间、持续时间和前置依赖。
- 拖动时显示箭头预览，松开连接；Esc、无效端点或取消拖动不会创建连接。循环依赖被阻止，关联允许成环。
- 连线默认无文字。双击连线可添加、修改或清空文字标注；也可右键操作。选中连线后按 Delete 可删除，Ctrl+Z 恢复。
- 箭头使用实心箭头、背景描边和较宽点击区域；选中动作时突出其相关连线。SVG 导出保留两类连接及自定义标注，CSV 增加关联/目标和连线标注列。

### 拖动时的虚线对齐提醒

动作起点或终点接近其他可见动作的起止时间时，显示竖向虚线和时间提示；准确对齐显示「对齐」，接近时显示「接近」。跨泳道移动时显示目标泳道中心的横向虚线；拉伸边缘也有时间对齐提示。松开、Esc 或取消后参考线消失。

参考线只提供视觉提醒；拖动仍遵循所选时间吸附粒度。折叠泳道的动作不参与提示。

### 5. 排练、导出、撤销

- 点击 `▶ 排练` 启动相对计时，红线标明当前进度；点击暂停，或 `↺ 归零`。
- `导出 CSV` 生成可用 Excel 打开的时间安排表。
- `导出 SVG` 生成可插入 PowerPoint 的矢量甘特图。
- 时间轴获得焦点时，`Ctrl + Z` / `Ctrl + Shift + Z` 可以撤销 / 重做；也可点工具栏按钮。

## 文件导入导出与 AI 优化

时间轴顶部「导入 / 导出」支持完整项目文件，CSV 和 SVG 继续用于排程表与图形展示。

1. 选择「导出完整项目 / AI 优化文件」，填写优化目标，例如“缩短总时长，减少飞手时间冲突，保留关键动作”。
2. 选择 **JSON（推荐）** 或 Markdown。文件保存到当前项目所在目录，包含全部分组、泳道、动作、备注、依赖、关联、标注、关键星标和项目正文。
3. 将文件交给你使用的 AI 工具，要求按文件中的约束优化并返回完整文件。JSON 内有 `aiGuide`、`project`、`markdownNotes` 与 `optimizationNotes`；Markdown 含排程概览和完整 `cueflow` 数据块。
4. 通过「导入项目文件」选择 AI 返回的 JSON/Markdown；也可选择「粘贴 AI 返回的项目」。原有 CueFlow Markdown 项目和裸项目 JSON 同样支持。
5. 预览动作增删、时间、关键标记、依赖、分组/泳道与关联的变化，再「保存为新项目」。原项目保留，可直接比较。AI 的优化说明一并保存到新项目。

导入会检查时间边界、ID/引用、循环依赖和文件格式。「按依赖自动顺延」开关会同步更新预览；关闭则按文件原始时间导入，并明确显示前置时间冲突。同泳道重叠会提示复核。文件大小上限 5 MB，单文件最多 3000 动作、500 泳道、10000 关联。

AI 优化由外部 AI 工具完成，插件提供完整数据、约束、变化预览与回导。详见 [项目文件格式与 AI 工作流](docs/PROJECT_FILES.md)。

## Markdown 数据结构

项目文件位于 `CueFlow/<项目名>.md`。每个文件含一个 `cueflow` 代码块：

````markdown
# 演示项目

```cueflow
{
  "version": 4,
  "groups": [{ "id": "pilots", "name": "飞手组" }],
  "name": "演示项目",
  "durationSec": 1200,
  "lanes": [{ "id": "lane-a", "name": "飞手 A", "color": "#0F9C91", "groupId": "pilots" }],
  "cues": [{
    "id": "cue-1",
    "name": "Mesh 组网确认",
    "laneId": "lane-a",
    "startSec": 192,
    "durationSec": 45,
    "status": "planned",
    "critical": false,
    "note": "T+03:12 开始，持续 45 秒",
    "dependsOn": []
  }],
  "relations": [],
  "dependencyLabels": []
}
```

## 导演备注
可自由写其他 Markdown。
````

`startSec` / `durationSec` 全部是**秒数**，例如 `T+03:12 → 192`。修改项目文件时请保留唯一的 `cueflow` JSON 代码块，并保证是合法 JSON。数据块以外的正文编辑可以与排程保存共存；同一数据块被外部修改时会阻止旧视图覆盖，并提示保存为副本或重新读取。

旧版项目可自动读取；保存后使用数据格式 4，以保留关键动作星标、关联和连线标注。回退到 0.7 或更早版本时，使用升级前的项目备份。

## 已知边界和待完善功能

- 当前主要是桌面端，`isDesktopOnly: true`；没有做移动端验收。
- **不是 dotpm 的扩展插件**，不与其任务数据双向同步，不包含 dotpm 的看板/表格/分派工作流。
- 秒级对齐通过吸附与缩放实现；当前**不支持帧级/毫秒级**拖动。
- 同泳道同时发生的任务会标红提示，但不会阻止排程；角色同时操作多设备的可行性仍需人为判断。
- 当前的依赖规则是 Finish-to-Start；不提供 Start-to-Start 等更复杂约束与提前/滞后量。
- 排练计时只供人工核对执行，不会向无人机或设备发送控制指令。
- 本地 Markdown 可结合 Obsidian 自有同步方案，但目前没有多人实时协同编辑或冲突合并。
- 外部编辑排程后，使用保存冲突提示中的「重新读取」，或先保存为副本；当前不提供自动合并。
- 本机基础验收覆盖 300 个动作、20 条泳道；1000 个动作完成探索性压力测试，但未作为长期稳定性承诺。
- 完整客户端检查、故障模拟、导出复核与性能数据见随附验收报告。验收范围为 Windows 桌面端、单人本地排程；尚未覆盖多人实时协作、移动端、长时间无人值守或设备控制。

## 开发与测试

本项目用不压缩的 `main.js` 直接发布，因此不依赖 TypeScript 构建工具，修改后复制三文件即可安装。

```bash
node --version   # 推荐 Node.js 18+
npm test
```

`npm run test:files` 检查完整文件往返、AI 修改、导入预览与新项目保存。`npm run test:selection` 检查本次框选、批量变换与关键动作逻辑。`npm run test:alignment` 检查对齐提示。`tests/connections-smoke.cjs` 覆盖连线语义、路径和标注；`tests/smoke.cjs` 检查时间/依赖/冲突等纯函数；`tests/storage-smoke.cjs` 检查 Markdown 保存、CSV/SVG 导出；`tests/browser-preview.html` 是未依赖真实 Obsidian 的试验性浏览器适配页，不代表客户端验收。

项目设计参考 dotpm 的理念与用户场景，代码未拷贝 dotpm 源码。
